# BCA 开发规则

更新：2026-10-25。当前授权为成熟区块链工具聚合的开发、验证、提交与推送，具体决定见 [QUESTIONS](QUESTIONS.md)。进度统一维护在 [STATUS](../STATUS.md)，历史分工见 tasks/。

## 每次开发

1. 从一个具体用户任务开始：明确输入、需要调用的官方工具和预期结果。
2. 在出错或缺能力的边界修改，复用共享 SDK/CLI/MCP 实现和成熟上游组件。
3. 先运行受影响的真实路径；失败后局部修复、局部复测。最终做一次必要构建。
4. 提交能够推进用户任务的代码，同步简短进度和实际未测项。

## 精简要求

- 编译、测试、部署按请求选择；查询不强制带出完整开发流程。
- 工具目录先返回摘要，需要某个工具时再取 Schema；诊断只解释缺项与修复动作。
- 不增加运行时自评、评分榜、覆盖率门槛、验收台账系统或重复状态副本。
- 每项新增抽象必须服务当前真实调用；已有 SDK/CLI/MCP 能完成的工作直接复用。
- 保留交易授权、输入校验、真实错误、超时清理、凭据保护与连接关闭。

## 验证与交付

使用真实文件、官方 SDK、必要的本地链或 MCP 服务。受控故障只验证错误传播，不替代业务结果。测试按改动选择，沿用现有脚本，不加测试框架或数量目标。

账户、资金、平台或网络缺项独立记录，不阻塞其他已授权开发。按既有决定保留开发分支/draft PR，完整生态验收后再合并；公开发布与生产交易继续遵守既有授权范围。
