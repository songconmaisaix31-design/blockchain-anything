# 做区块链的 AWS：商业故事

> 对外叙事主稿 · v1（2026-10-31）
> 配套：[商业模式与定价](BUSINESS.md) · [上游价目与对标](UPSTREAM-APIS.md) · [长期展望](VISION.md) · [集成规划](INTEGRATIONS.md)
>
> 这份文档不谈功能，只讲一件事：**这个产品在产业版图里占哪个位置，以及为什么这个位置值钱。**

---

## 一句话

**AWS 卖的不是服务器，是一张能力清单、一个按调用跳的计数器、一张把所有供应商并进来的账单。区块链这一层，前三样都还没有人做全——我们做那张账单。**

---

## 一、先把"区块链的 AWS"这句话拆开

这个类比被用滥了，所以必须拆清楚它到底指什么。AWS 值钱的地方不在机房，在三件互锁的东西：

| 层 | AWS 的做法 | 为什么值钱 |
| --- | --- | --- |
| **原语目录** | 2006 年只有 S3 和 EC2 两个；今天 200+ 服务，每个都是"一个 API + 一份文档 + 一个价格" | 客户不需要知道背后是哪种服务器，只需要知道调哪个接口 |
| **计量与账单** | 按秒、按调用、按 GB 计费；没有销售、没有合同、没有最低消费 | 开发者可以先花 3 美元试，再决定要不要押上整个公司 |
| **市场** | Marketplace：第三方的能力上架，走同一张账单结算 | 生态自己长出来，平台收租 |

2025 财年 AWS 营收 **\$1,287 亿**（Q4 \$356 亿，同比 +24%），年化运行率 **\$1,420 亿**，全球份额 **28%**，Q4 经营利润率 35%，贡献了亚马逊 **57%** 的经营利润。

一个人会误读这个数字：以为它赢在"基础设施规模"。**它赢在把基础设施变成了可计量的 API 调用。** 规模是结果，不是原因。

---

## 二、十年前那批"区块链 AWS"是怎么死的

这是这个故事里最该讲清楚的一段，因为它决定了我们**不能**做什么。

| 项目 | 做了什么 | 结局 |
| --- | --- | --- |
| Azure Blockchain Service | 在 Azure 上一键起 Quorum / Fabric 联盟链 | **2021-09-10 退役**，用户被引导迁到 ConsenSys Quorum |
| IBM Blockchain Platform | Hyperledger Fabric 的企业发行版 + 运维 | **2023-04-30 结束支持** |
| Kaleido | 联盟链即服务，多协议多区域 | 转型为机构代币化与数字资产平台（BaaS 心智份额一年从 16.1% 掉到 11.5%） |
| Amazon Managed Blockchain | Fabric / Ethereum 托管网络 | 仍在，但定位是企业联盟链编排，不是开发者能力层 |

它们失败的原因高度一致，而且是**同一个错误**：

> **它们卖的是"一条链"，客户要的是"一个能力"。**
> 一条链需要治理——谁加入、谁升级、规则怎么改；一个能力只需要调用。

联盟链的难点从来不在"把链跑起来"，在参与方对规则、数据口径、升级节奏的持续对齐。卖基础设施的人被迫进入客户的治理会议，而卖 API 的人只出现在账单上。前者是项目制生意，后者是复利生意。

**结论：任何需要客户先"治理"才能用的产品，都不是 AWS。** 这条直接排除了我们去卖联盟链、卖节点集群、卖私有链部署。

---

## 三、真正做成的那些，都是同一个动作

| 公司 | 抽象掉的是什么 | 卖的是什么 | 结果 |
| --- | --- | --- | --- |
| **Twilio** | 各国运营商、短信网关、语音线路 | 一条 API + 一条账单 | 通信 API 的品类定义者，上市 |
| **Stripe** | 收单行、风控、对账、退税 | 一次调用 + 2.9% + 30¢ | 最有价值的支付基础设施之一 |
| **Plaid** | 数千家银行各不相同的私有接口 | 一个 `/accounts` 端点 | Visa 曾出 **53 亿美元**收购（被监管否决） |
| **Segment** | 每个 SaaS 各不相同的埋点 SDK | 一个 `collect` 端点 | Twilio **32 亿美元**收购 |
| **Datadog** | 各种监控 agent 与后端 | 一个面板 + 按主机计费 | 上市公司 |
| **Alchemy / Infura** | 节点运维、归档、扩容 | RPC 调用 | Alchemy 15 万+ 团队、年交易额 \$1T+、100+ 链 |

提炼出四条判据（这就是我们的产品纪律）：

1. **抽象的是"供应商"，不是"技术"。** Twilio 抽象运营商；Plaid 抽象银行。抽象技术（"我给你一条链"）的人，最后都在给客户做实施。
2. **计价单位必须客户能预判。** 页数、调用数、主机数——不是"算力单位"。算不清账的客户不敢放量。
3. **免费额度要够跑完一次真实任务。** Stripe 有测试模式，Plaid 有沙箱，Alchemy 送 3,000 万 CU。试用门槛决定漏斗宽度。
4. **赢家最后都长出了市场。** AWS Marketplace、Twilio 的 add-on、QuickNode 的 add-on marketplace（Flashbots、Blockscout、Covalent 都挂在上面）。**平台自己造血不够，要让别人在你的账单上赚钱。**

## 四、"区块链的 AWS"这个称号已经有人占了

必须承认：**Alchemy 就是今天的"区块链 AWS"。** 15 万+ 团队、\$1T+ 年交易额、100+ 条链、99.99% 可用性，而且已经出了 160+ 个工具的 MCP server、CLI、Agent Skills、免密钥注册——它比多数人以为的更靠近 agent 时代。

所以我们的故事**不能**是"我们也是 AWS"，那会被一句话问死：*你和 Alchemy 有什么区别？*

正确的说法是把 AWS 拆层，只抢一层：

> **Alchemy 是这一层的 EC2。我们做它上面那张账单。**
> EC2 只有一个供应商；账单可以有很多供应商。AWS 之所以是 AWS，是因为它后来长出了 200 个服务和一整个 Marketplace——而不是因为它是最大的那台机器。

这个位置在别的行业有先例，而且都成立过：Twilio 不拥有任何运营商，Datadog 不拥有任何一台被监控的机器，Plaid 不拥有任何一家银行。**它们的位置不是"更强的上游"，是"上游之上唯一的那张账单"。**

---

## 五、我们的三层，现在缺哪一层

| 层 | AWS | BCA 现状 | 判断 |
| --- | --- | --- | --- |
| **原语目录** | 200+ 服务 | **152 个工具 / 65 个上游**，每个带 schema、只读/可写标记、失败语义 | 数量够了。再堆工具是边际收益递减 |
| **计量与账单** | 按秒/按调用 | credits 三档（\$19 / \$79 / \$299），BYO 免费 | 有，但分档太粗——成本跨 5 个数量级，必须改五档 |
| **市场** | Marketplace，第三方上架、同一张账单 | **没有** | **这才是真正的缺口** |

看清这件事很重要：**我们不缺工具，缺的是"让别人的能力进我们账单"的那一层。**

现在的 65 个上游，是我们一家一家接进来的——这是劳动密集型生意，规模不经济。真正的 AWS 时刻是：**上游自己把工具注册进来，我们只提供目录、计量、结算和信任背书，抽 15%–20%。** Apify 已经在这么做（开发者拿 80%，平台抽 20%），QuickNode 也在这么做（add-on marketplace）。我们还没有。

## 六、钱的来源：三种人，三种理由

| 客户 | 他们现在怎么活 | 为什么付钱 | 愿意付多少 |
| --- | --- | --- | --- |
| **独立开发者 / vibe coder** | 注册 8–12 个账号，管 8–12 把 key，一个个读文档 | 省事：接一次 MCP，全通 | \$19/月，年付 \$16 |
| **小团队产品方** | 自己维护适配层，schema 一变就崩 | 稳定：schema 漂移、限流、重试有人兜 | \$79–299/月 |
| **机构 / 有合规要求** | 每个上游单独采购、单独审计 | 责任：审计日志、SLA、可私有化、说得清数据出处 | 定制 |

一句话概括定价哲学：**我们不卖数据，我们卖"不用跟 65 个供应商分别打交道"。**

## 七、路线图：四层，每层一年

| 阶段 | 时间 | 做什么 | 成功的样子 |
| --- | --- | --- | --- |
| **一 · 能力层**（现在） | 已完成 | 152 工具 / 65 上游，标注质量、只读优先、写入闸门 | 装得上、跑得通、敢给别人演示 |
| **二 · 账单层** | 6–12 个月 | credits 改五档；x402 按次报价；团队子账号与用量隔离 | 有第一个付 \$79 且第二个月还在付的人 |
| **三 · 市场层** | 12–24 个月 | 第三方工具注册进目录，抽 15%–20%，同一套 credits 结算 | 目录里 >30% 的工具不是我们写的 |
| **四 · 身份层** | 24 个月+ | agent 的钱包、授权、限额、可撤销的签名权 | agent 拿着 BCA 的身份去签名，而不是拿着用户的私钥 |

第四层才是终局：链上一切最终都要签名，**谁掌握 agent 的签名权，谁就是这一层的 AWS**。前三层都是在为这一层积累"我知道每个工具值不值得信"的判断力。

## 八、反向自检：凭什么不是他们

故事讲得再好，也要能回答三个"如果他们做了呢"。

**Q：Alchemy 把 MCP 做到 300 个工具怎么办？**
它做得到，但说不出一句话：**"别家用我更便宜"**。单家上游永远不能做跨家比较，因为比较会稀释自家数据。我们的位置建立在"不站队"上——这不是技术壁垒，是动机壁垒，而动机壁垒比技术壁垒活得久。

**Q：AWS 自己出一个？**
它缺三样东西：链上语义（ABI、精度、失败语义、Safe Harbor 这类制度安排）、65 家小上游的适配意愿、以及"愿意为一条 3 美元的调用服务"的组织结构。AWS 的销售模型服务不了这种长尾。

**Q：Anthropic / OpenAI 直接接 20 家不就行了？**
接 10 家可以，接 65 家带失败语义、带成本标注、带写入闸门的，不是模型公司愿意做的活。它们要的是"能力已经存在且可靠"，而不是"去把 65 个 API 的怪癖一个个磨平"。**我们做的正是它们最不想做的那部分。**

**一个诚实的边界**：这个位置只在"上游足够多、判定足够难"时成立。如果某天链上能力收敛到 3 家供应商、语义完全标准化，我们就失去存在理由。所以路线图必须往"判定"走，而不是往"更多工具"走——**工具数量是我们的现在是别人的未来，判断力才是护城河。**

## 九、60 秒口播稿

> 2010 年代，所有人都想做"区块链的 AWS"。微软做了，2021 年关了；IBM 做了，2023 年停了。原因只有一个：**他们卖的是"一条链"，客户要的是"一个能力"。** 一条链需要治理，一个能力只需要调用。
>
> 真正做成的人，做的都是同一件事：把很多供应商抽象成一个 API、一张账单。Twilio 抽象运营商，Plaid 抽象银行，Stripe 抽象收单行。今天这一层在链上已经有人占住了一半——Alchemy 就是区块链的 EC2，15 万团队、100 条链。
>
> 但 EC2 之上还有账单。**AWS 之所以是 AWS，不是因为它有最大的机器，是因为它后来长出了 200 个服务和整个 Marketplace。**
>
> 我们做的是那张账单：152 个工具、65 个上游，每个工具标好价格和风险，接一次 MCP 全通。开源免费、自带密钥免费、托管 \$19 起。第三年，我们要让别人的工具也挂到这张账单上——那才是 AWS 真正开始的地方。

---

## 十、讲这个故事时的三条禁忌

1. **不要说"我们是区块链的 AWS"。** 说"我们做 AWS 的账单层"。前者是空话，后者是可验证的位置。
2. **不要用工具数量当卖点。** 152 是我们的现状，不是别人的门槛——Alchemy 已经有 160 个。数量会被追上，判断力不会。
3. **不要回避失败案例。** Azure 和 IBM 的死法是这个故事里最有说服力的部分，因为它是**别人已经替我们付过的学费**。讲清楚它，比讲十个优势都有用。
