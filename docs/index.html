01 / WHY

为什么是"用户视角"

市面上的 Web3 工具大多只面向懂合约的开发者。"所有人都可以写合约"是技术视角——它假设你关心 Solidity、RPC 和 gas 参数。Blockchain Anything 站在用户视角：所有人都可以创造自己的链上产品。

传统 Web3 工具Blockchain Anything
面向对象懂 Solidity 的开发者有想法的任何人
表达方式写合约、配环境、调 RPC用自然语言描述想法
交付物一份合约源码可发布、可运行的链上产品
失败成本编译报错、部署踩坑规则先跑一遍，通过再上链
接入方式逐个 SDK 集成一套 MCP 工具集，任意 Agent 调用

一次完整的创造流程

描述想法  →  Agent 理解意图
          →  发现需要的链上工具      bca find
          →  生成规则并实现          bca init / build
          →  本地跑一遍真正验证      bca test
          →  核对权限与写操作边界     bca doctor
          →  钱包授权，发布上链      工作站 / 宿主钱包

分工是明确的：Agent 负责对话、理解与任务循环，BCA 提供工具发现、项目操作、连接管理与真实结果。二者通过 MCP 协议衔接，CLI、MCP 与 TypeScript SDK 共用同一套实现。

合约编译、单元测试、本地链试运行都在本机完成，不需要 RPC、不需要签名权限——"试运行规则"是真实可用的，不是一句宣传语。写操作需显式授权：公共链交易沿用宿主钱包授权流程，本地一键部署仅面向明确批准的 loopback Anvil 操作。

02 / QUICK START

一条命令，安装到项目

准备 Node 22.12+（22 LTS）或 Node 24 LTS、npm 和 Git，在目标项目目录执行：

npm exec --yes --package=git+https://github.com/songconmaisaix31-design/blockchain-anything.git#main -- bca setup --client both --install

首次下载和构建需要联网。包从 GitHub 源码安装，尚未发布到公共 npm。只使用一个客户端时，将 both 换为 codex 或 claude。中国大陆网络环境下，镜像缺版本时为 npm 命令加 --registry=https://registry.npmjs.org。

安装会生成项目 MCP 配置与工作流，保留现有条目并备份变更。随后在客户端信任该项目并批准 MCP，就可以直接用自然语言提出任务。

从终端运行

node .bca/runtime/node_modules/blockchain-anything/dist/cli/main.js doctor

后续命令中的 bca 可替换为上面的 node …/cli/main.js。Windows x64 直接使用 PowerShell，无需修改全局 Bash 配置。完整安装说明 ↗

03 / BUSINESS

免费能用，付费省事

BCA 采用 open-core：框架开源、自带密钥免费、托管付费。自己配上游密钥跑 BCA 永远免费且不限量——你的成本就是你自己的上游账单。愿意付钱的人买的是另一件事：不用自己申请和管理十几个上游密钥，注册完就能用。

credits 怎么算

由执行代价决定，不由"工具看起来重不重要"决定：本地计算 0 credit，只读链上查询 1 credit，第三方付费上游 3–4 credits。调用失败不计费，写操作不进入计量——不靠多写链赚钱，权限与授权是安全边界，不是收费点。

04 / SCENARIOS

NFT 是入口，不是终点

NFT 是最直观的第一个入口——它是普通人最容易理解的链上规则形式。同一套能力可以延伸到更远的地方：

社群会员凭证即身份，权限规则写在链上，不再依赖中心化后台
电子票务可验证的发行来源与流转记录，天然防伪
链上游戏资产归属与规则公开，玩家真正拥有道具
多人协作所有权与贡献可追溯，分配规则自动执行
数字所有权凭证从内容到 AI 产出，锚定不可篡改的归属与来源
05 / CAPABILITIES

标准化 MCP 工具集

BCA 封装以太坊等多条成熟公链的生态能力，把合约部署、mint、链上身份、交易查询、资产上链打包成标准化 MCP 工具集。当前注册 127 个工具，全部标注来源组件、只读/写性质与前置要求，由 capability_search 统一检索。

领域工具前缀覆盖能力
合约开发dev_* / project_*项目初始化、编译、测试、Foundry/Hardhat 双栈
EVM 读写与诊断evm_* / viem_* / workstation_*链状态读取、trace 组合、代理识别、失败归因
链上身份与凭证eas_* / did_* / vc_* / sas_* / sign_*声明、签名、凭证、撤销、信任链
资产与存储ipfs_* / arweave_* / walrus_* / seal_*CID 计算、去中心化存储、加密访问控制
多链生态solana_* / sui_* / aptos_* / safe_* / x402_*跨链读写、多签、链上支付
交易与风控ccxt_* / goplus_* / hummingbot_* / ots_*行情、策略、代币安全、区块浏览器数据
来源与审计slsa_* / cosign_* / c2pa_* / provenance_*软件供应链证明、内容来源、零知识证明

每条工具都保留原始来源组件，不重复实现 ABI 编码、签名或 CID 等已成熟的基础能力。任意兼容 MCP 的 AI Agent 都可以直接调用这套能力。

06 / ROADMAP

给 Agent 一个不可篡改的身份

让普通人创造链上规则是第一步。下一个问题是：当大量 Agent 开始替人行动时，谁为它们的行为负责，又能被谁追溯？

BCA 后续支持为 Agent 分配不可篡改的链上身份，把注册信息、交互记录与经验资产锚定在链上，让 A2A（Agent-to-Agent）交互全程可追溯。

它可以与蜂群 Agent 系统联动，让大量自主智能体拥有可信的链上身份、资产与可审计交互日志。这一步建立在当前已有的 agent_*、sign_*、身份适配与来源验证（SLSA、in-toto、C2PA）能力之上。

08 / KNOWN LIMITS

使用前了解这些边界

  • 账户型服务需要自行配置授权；工具目录不授予钱包或写入权限。
  • 公共链交易沿用宿主授权流程。内置一键部署仅面向明确批准的本地 Anvil 操作。
  • Windows / macOS 原生客户端 UI、公共测试网源码上传仍需分项验证。
  • 部分上游依赖仍有安全告警，详见依赖安全状态。
