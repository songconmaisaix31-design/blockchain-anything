## 失败、修复与局部复测

1. **Safe 自定义网络配置缺口**：初次 `safe_info` 和 `safe_prepare` 均报 `Invalid multiSend contract address`。加入 `BCA_SAFE_CONTRACT_NETWORKS`，校验地址后直接传给官方 `Safe.init`；没有自研交易编码。部署官方 MultiSend/MultiSendCallOnly 后，仅重跑 Safe，batch hash 与真实合约计算一致。修复后的构建及局部复测均通过。
2. **SAS 验收样本选择错误**：sas-lib 生成的枚举是目录排序，不能作为链上 discriminator。第一次按枚举筛选时选错账户；核对官方 Rust 定义（Credential=0、Schema=1、Attestation=2）后仅重新读取对应样本成功，无需修改产品解码代码。
3. **C2PA 本地程序权限**：下载解压后的二进制缺可执行位，首次 EACCES；赋予执行权限后仅重跑 `c2pa_inspect` 成功，保留官方证书信任失败状态。
4. **Slither MCP 浮动依赖与目录配置**：首次启动连接关闭；安装完成后，官方客户端确认初始化成功，但 tools/list 因上游 Pydantic 序列化循环引用失败。按源码提交的 uv.lock 固定 FastMCP 2.14.3、MCP 1.25.0、Pydantic 2.12.5 后发现 23 工具。初次业务调用按不正确的参数层级失败，按实际 Schema 的 request.path 修正；随后分析报相对 import 不存在。将 MCP cwd 对齐分析项目后，真实分析返回 structuredContent.success=true、9 个合约。示例已固定官方源码版本和这些依赖，并配置项目 cwd；不修改上游代码。
5. **OpenTimestamps 环境缺失**：原生 CLI 明确报告没有 Bitcoin 节点认证配置；未忽略验证、未改为假成功。
