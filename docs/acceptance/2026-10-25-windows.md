## 已复现问题

### 默认依赖安装失败

命令：`npm ci --no-audit --no-fund`，退出 1。

固定依赖 `@foundry-rs/forge@1.7.1` 的 postinstall 为 `TARGET_TOOL=forge node ./postinstall.mjs`。npm 使用 `cmd.exe /d /s /c` 执行时返回：

```text
'TARGET_TOOL' is not recognized as an internal or external command,
operable program or batch file.
```

官方 registry 对相同固定版本 cast/anvil 的元数据也显示相同环境变量赋值语法。故障影响默认 checkout 安装；干净 Windows 上安装这些 Foundry npm 包也会遇到同一脚本问题。日志：`.work/windows-npm-ci.log`。日志中另有失败清理期间的 EBUSY/EPERM 提示。

### Windows 客户端诊断误报

PowerShell 的 `codex --version`、`claude --version`、`npm --version` 均成功。BCA `run('codex'/'claude'/'npm', ['--version'], ...)` 均返回 `spawn ... ENOENT`，对应 `runVersion` 返回 `null`。

原因位于 `src/development/exec.ts` 的 `shell:false` 子进程启动路径；这台机器的入口为 npm 生成的 `.cmd/.ps1`。`src/setup.ts` 中 doctor 对 Codex/Claude 采用这条路径，实际已安装客户端会被诊断为不可用。产品 `runNpm(['--version'])` 使用 npm 的 JavaScript 入口，实测成功。

同一问题影响 `scripts/check-setup.ts` 第 11、24 行的 `run('npm', ...)`，因此该脚本的 Windows 入口不能代表产品 setup 的实际结果。

### setup 返回的下一条命令无法直接在 PowerShell 使用

真实 setup 成功返回后，`nextCommand` 将 Windows 路径按 JSON 字符串转义并拼接，缺少 PowerShell 的调用运算符。将实际返回文本交给 PowerShell Parser 后产生两项 `UnexpectedToken`。位置：`src/setup.ts` 第 110 行。

当前 checkout 可使用 PowerShell 的正常调用语法：

```powershell
& 'C:\Program Files\nodejs\node.exe' 'C:\Users\DW\orca\blockchain-anything\dist\cli\main.js' doctor
```

这不影响 setup 已生成的 JSON/TOML 配置中的独立 command/args；实际官方 MCP 客户端已按该配置成功连接并调用。

### 进程树清理未满足返回时停止的要求

使用真实 Node 父进程启动真实后代，每 20ms 向 `.work/` 文件追加内容，调用 BCA 原有 `run` 测试超时与取消。没有模拟命令或服务。

- 首次超时检查返回后，文件大小从 105 字节增长至 300ms 后的 115 字节，随后到 116 字节才停止，断言失败。
- 分阶段观察中，3000ms 超时在约 5131ms 返回“进程树清理未在 2000ms 内确认”；返回后约 2139ms，文件仍由 114 增长至 173 字节，父子 PID 均存活。
- 取消操作同样返回清理未确认，返回后约 2031ms 文件由 65 增长至 126 字节，父子 PID 均存活。测试显式清理了这些进程。
- 普通命令退出 0；输出超限返回明确错误。

`src/development/exec.ts` 在 Windows 异步启动 taskkill，并在父进程 close 时清除清理计时器、结束 Promise，没有等待 taskkill 的 close；taskkill 自身还有 1500ms 终止计时。清理期限不足时会报告未知状态。上述观察不能作为进程树成功清理的结果。

命令和证据：`node .work/windows-process-check.mjs`、`node .work/windows-process-observe.mjs`，均退出 1；`.work/windows-process.log`、`.work/windows-process-observations.json`。
