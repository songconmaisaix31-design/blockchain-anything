# BCA 精简与任务入口验收

日期：2026-10-25（Asia/Shanghai）。审阅基线：`f3a71ffd5ab56375e19ca84fcc9591d4a2919ce5`。实现与本报告同次提交，见 [PR #1](https://github.com/songconmaisaix31-design/blockchain-anything/pull/1)。环境：Linux x64、Node 24.22.1；复用 lockfile 中的官方依赖。

## 审阅结论与改动

现有官方工具适配、共享入口、错误传播、交易授权、进程清理和 MCP 会话有实际用途。主要冗余在固定的全流程计划、重复状态描述和目录输出，没有依据为“减行数”删除整个供应商适配。

| 问题与定位 | 用户影响 | 本轮处理 |
| --- | --- | --- |
| `workstations/catalog.ts` 将开发任务绑定六步流程 | “只编译合约”仍要求部署写权限/RPC，被标为不可执行 | 按 compile/test/deploy/develop 生成必要步骤；不强制读取生成技能；不重复查询交易回执 |
| `toolkit.ts` 把每次未抛异常的调用记作 verification | 通用成功码无法表达各业务验证结果；内存表既不记录参数，也不跨进程保留 | 删除 Map、通用记录逻辑及 availability.verification；保留原始业务结果与历史验收 |
| `capability_list`、doctor 默认重复全部 Schema 与元数据 | 简单诊断返回大段与当前任务无关的说明 | 目录默认摘要，指定 name/details 取详细信息；doctor 按状态汇总 |
| guide 重复项目依赖、可选能力状态及 lifecycle/执行标记 | 每次检索携带大量推导状态，宿主还被要求再调用 guide | 删除重复副本，搜索结果可直接使用；可选工具只列名称 |
| Hardhat 可用性只检查根目录 | 实际装在子项目的 Hardhat 被误报未安装 | 根据请求的 dir 检查，与实际执行目录一致 |
| doctor 同时要求两个客户端 | 只使用 Claude 的项目也被 Codex 缺失阻塞 | 只检查本次目录已有配置的客户端；未使用的 Foundry 组件缺失单列 |
| STATUS 与任务文档重复验收及历史分工 | 接手容易沿用过期任务、维护多套状态 | STATUS 改为短索引；TASKS 保留当前开发规则，历史证据保留原处 |

新增 CLI `bca find "只编译合约" --dir examples/contracts`，直接复用共享检索实现。主帮助现在列出 find/setup/doctor。SDK/MCP 工具名保持；目录详细输出使用 `capability_list({name})` 或 `details:true`，删除字段详见工作站指南。没有引入依赖、运行时框架或测试框架。

## 首次失败与局部处理

- 隔离 worktree 使用外部 node_modules 软链接时，Solidity import 被现有工作目录边界检查拒绝；改用工作树内的依赖目录，无须放宽产品路径保护。
- 首次 Foundry 离线构建缺少原生 solc 0.8.35；通过官方 Forge 正常构建准备该版本后，相关工作流复跑通过。
- 旧进程测试在后代尚未启动时便触发 500ms 超时，随后 stat 不存在的 marker。脚本增加启动余量，确认写入发生，并在取消前等待写入；仍验证后代停止写入和 2 秒清理边界。
- Hardhat 离线安装无缓存；从官方 npm 安装固定版本后验证真实子项目。

## 尚未覆盖

Windows 原生/WSL2 宿主和客户端 UI 授权、账户型服务及公共测试网源码上传验证沿用 [既有交接](BCA-LOCAL-AGENT-HANDOFF-20261024.md)。本轮没有重复全生态、安装包下载链路或未修改的官方 MCP 会话验收，也未重新运行 Hardhat 测试/部署。

自然语言任务选择仍是简单规则，含否定或多意图的问题可用 context.task / --task 明确目标。工作站只是返回步骤，执行前由宿主补全真实参数和授权。保留 private:true 和现有 draft PR，不合并 main、不发布 npm、不执行生产交易。
