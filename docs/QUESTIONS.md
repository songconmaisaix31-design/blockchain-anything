| 编号 | 完整方案中的建议 | 影响 |
| --- | --- | --- |

| Q03 | BCA 稳定主体由签名控制声明管理；did:key 标识签署密钥、did:pkh 关联链账户；ERC-8004 仅为可选外部身份关联 | 是否接受 NFT 身份的外部关联及控制权转移语义 |
| Q04 | 离线签名使用标准密钥与信封；线上 EVM 提交使用外部钱包或 Safe；Biscuit 服务侧授权的同主体收缩可离线进行，跨主体子授权由获授权发行服务签发；撤销来源与状态期限显式配置 | 密钥托管、发行服务参与再委派、Agent 自主范围、恢复阈值/等待期/挑战与控制者；Safe 各签名路径分别验收 |
| Q05 | 敏感内容默认本地或私有对象存储，加密格式建议 age v1；公开数据可选 IPFS。承诺模式建议采用 RFC 9901 SD-JWT、SHA-256、独立 32 字节随机盐和受控 disclosures；Arweave、Walrus 按保留与公开要求选择 | 数据公开、加密与选择披露 profile、存储成本、删除和续期责任 |
| Q06 | 首个真实案例建议采用 Agent 创建的公开 Git 项目：输入对象、工具调用、产物和独立校验组成完整声明链 | 具体项目、任务、允许工具和验证者仍需指定 |
| Q07 | 核心交付包含完整的 EVM 生命周期、授权、隐私、组合验证、CLI/MCP 与真实 Codex 验收；扩展链、行业导入器和 ZK 各自验收 | 首次发布边界，不将未实现扩展能力列入已支持清单 |

本轮无须提前提供钱包私钥、API secret 或生产资金。后续测试钱包、测试网余额、私有存储凭证和恢复控制者按已确认任务配置；密钥通过约定的安全存储提供。
