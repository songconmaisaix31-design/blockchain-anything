# 靠近钱的边界：白帽救援、套利复刻与资金流技术栈

> 调研时间：2026-10-31 · 所有"可用性"结论均有实测记录，未实测的会明确标注
> 本文讨论的是**防御与验证**，不含任何攻击手法教学。涉及真实资金的动作一律不自动化。

## 0. 一句话结论

三个方向里，**白帽救援是唯一同时满足"合法、可演示、有制度红利、竞争尚未饱和"的**；"找套利钱包并复刻"技术上完全可行，但经济上已是红海——它的真实价值不在抢跑，而在**解释与验证**。而这两件事，恰好是同一台引擎。

## 1. 先纠正一个认知：这两件事是同一套技术

套利复刻、攻击复现、白帽救援，三者共用同一条流水线：

```
fork 主网状态（某一区块）
      ↓
重放 / 模拟一笔交易（或用你的地址重跑）
      ↓
计算资产变化 delta（token + ETH + NFT）
      ↓
     delta 的符号决定你在做什么
```

| 场景 | delta | 谁收钱 | 合法性 |
|---|---|---|---|
| 攻击复现 | 负（受害者视角） | 攻击者 | 只读复盘，合法 |
| 套利复刻 | 正 | 你 | 合法（公开市场竞争） |
| 白帽救援 | 正 | **协议**（不是你） | **需要授权，见第 3 节** |

区别只在最后一步"钱进谁的口袋"，前面 90% 的工程完全一样。这意味着：**做一套 fork 重放引擎，三个方向同时具备**。这也是为什么我建议技术投入集中在这一层，而不是分散做三套东西。

**已实测**：本地 anvil fork 到区块 `26310273`，读到 Vitalik 余额 5.7796 ETH、Uniswap V3 池子 `sqrtPriceX96` 可正常解析。复刻能力可用，且不依赖任何付费服务。

## 2. 白帽方向：这个市场是真的，而且有制度缺口

### 2.1 近期真实案例（说明规模与节奏）

| 事件 | 时间 | 损失 | 救援结果 |
|---|---|---|---|
| Balancer V2 稳定池 | 2025-11 | 约 $100M | Hypernative 21 分钟内锁定可暂停池；白帽追回约 $21M+（StakeWise 5,041 osETH ≈ $19M） |
| Coldcard 熵缺陷 | 2026-09 | 约 1,870 BTC | 联盟白帽抢跑 52.37 BTC（$4.5M），转入 Wyoming 法定信托 |
| Flooring Protocol | 2026-06 | 池子被抽干 | 0xQuit 抢救 68 个 NFT（29 BAYC、2 Punk），$500K+ |
| Magic Eden 旧合约授权 | 2026-09 | 660 WETH 丢失 | 抢救 23,155 个 NFT（$6M），但 WETH 无法拦截 |

最后一条最值得注意：**可替代资产救不回来，唯一性的资产能救**。因为 NFT 能被"搬到一个安全地址"，而 ERC-20 一旦转出就是无数个相同的单位，没有东西可以"抓住"。这个物理约束决定了救援工具的设计——**救援的第一动作是抢在转移之前，而不是转移之后追回**。

### 2.2 真正的护城河是法律，不是代码

SEAL（Security Alliance，samczsun 发起）的 **Whitehat Safe Harbor** 是目前唯一被广泛采用的制度性基础设施：

- **性质**：协议对"任何白帽"发出的**公开单方要约**，白帽无需事先认识、无需签约，只要按规则行动即受保护
- **适用条件**：仅限**正在发生或迫在眉睫**的攻击（例如恶意交易已在 mempool 中）。**不适用于**还有时间走漏洞披露的情况
- **核心义务**：72 小时内把资金归还到协议指定的 Asset Recovery Address，赏金按预定条款自动生效、不可谈判
- **覆盖规模**：20+ 协议、约 **$68B TVL**，含 Uniswap、Aave、Pendle、PancakeSwap、Balancer、Silo、zkSync
- **已追回**：SEAL911 + 白帽社区累计 **$150M+**
- **登记方式**：链上 `SafeHarborRegistry`（V3，2026-01 由 Cyfrin 审计），通过 CreateX 在各 EVM 链部署在同一地址 `0x326733493E143b8904716E7A64A9f4fb6A185a2c`

两个真实条款，能看出这个市场的定价：

| 协议 | 赏金 | 上限 | 身份要求 |
|---|---|---|---|
| Aave | 追回金额的 10% | 每人每事件 $1M | 实名 + KYC + 全球制裁筛查 |
| Lido | 追回金额的 10% | 每人每事件 $2M | 匿名 + 年龄/制裁/12 个月无关联的 attestation |

**这就是"和钱更近"的具体含义**：一次成功的救援，收益是追回金额的 10%，上限百万美元级。而投入是——一个能在 20 分钟内完成"检测 → 复现 → 构造 → 提交"的流水线。

### 2.3 SEAL 明确排除的情形（必须知道）

- ❌ 自己发起攻击、再用另一个地址"救援" → 仍算黑帽，无赏金、无保护、全额担责
- ❌ 攻击尚未发生、本可通过披露解决 → 不受保护
- ⚠️ 框架**不为白帽的行为合法性背书**，框架外的刑事责任仍由个人承担
- 建议协议把 Safe Harbor 赏金上限设在**低于**常规漏洞赏金，避免"制造攻击再救援"的套利

### 2.4 技术栈拆解（五段，每段都有明确的可接入性）

| 段 | 做什么 | 现成方案 | 成本 | 我们的可接入性 |
|---|---|---|---|---|
| ① 监控 | 盯 mempool 的 pending 交易 + 大额异动 | Forta Attack Detector、Hypernative、Ironblocks、Hexagate、自建 | Forta **$399/月**；Ironblocks **$1,289/月**；Hypernative 企业议价 | **公共 RPC 已可直接读 `txpool_status` / `eth_pendingTransactions`**（实测可用），无需付费 |
| ② 判定 | 判断"是否攻击"而非"是否异常" | 模式库 + 规则 + ML | 自建为主 | 空白，需自建；DeFiHackLabs 894 个 PoC 是现成训练集 |
| ③ 复现 | fork 到攻击前一区块，重放，算损失 | Foundry / anvil / revm / Tenderly | Tenderly 有免费额度 | **已具备**（anvil fork 实测通过） |
| ④ 构造 | 复用攻击 calldata，把收款方改成恢复地址；或直接调用 pause | 自写救援合约 | 自建 | 空白 |
| ⑤ 提交 | 私有 bundle，抢在攻击者之前上链 | Flashbots / bloXroute / MEV-Share | 免费 + 小费 | **relay 数据接口已实测可用**；提交需要签名密钥 |

**这段表格说明一件重要的事**：①③⑤ 三段已有免费或廉价路径，②④ 是真正的空白。而 ②④ 恰好是"agent 能提供价值"的地方——把 trace 翻译成人话、把模式匹配成结论、把救援 calldata 生成成草案。

## 3. 套利方向：先把"能赢的"和"赢不了的"分开

### 3.1 策略分层（诚实版）

| 策略 | 边际来源 | 谁在赢 | 零售可行性 |
|---|---|---|---|
| 三明治 | 吃散户滑点 | 专业 searcher + 私有通道 | ❌ **明确不做**（对抗性、监管风险、正在被私有 mempool 消灭） |
| 纯 DEX-DEX 三角 | 毫秒级延迟 | 与 relay 同机房的团队 | ❌ 基本无 |
| 清算 | gas 竞价 + 协议集成深度 | 专业 keeper | ⚠️ 中等，窗口在预言机更新前后 |
| 预言机延迟 | Chainlink/Pyth 更新与 DEX 价格的时序差 | 监控做得好的人 | ✅ 有窗口 |
| 稳定币脱锚 / LST 基差 | 资金成本 + 耐心 | 有资金的人 | ✅ 可做，慢但稳 |
| 长尾新池 / 新链 | 竞争密度低 | 愿意承担风险的人 | ✅ 机会最多 |
| CEX-DEX | 库存 + 双边速度 | 做市商 | ⚠️ 需要 CEX 账户与预置资金 |

### 3.2 找"套利钱包"到底找什么

不是找"赚得多的地址"，而是找**行为指纹**。可判定的六个维度：

1. **原子性**：单笔交易内完成多跳、无跨块持仓 → 套利而非投资
2. **资金零留存**：交易前后余额差 ≈ 利润，无本金沉淀 → 闪电贷
3. **gas 出价习惯**：稳定溢价而非随行情波动 → 有自动化竞价
4. **失败率**：低失败率说明本地有模拟（没模拟的机器人失败率会高得多）
5. **路径重复度**：反复使用同一组 router / 池子 → 有固定策略模板
6. **活跃区块分布**：是否只在特定事件（大额 swap、预言机更新）后出现

数据来源：EigenPhi（MEV 分类 API，需 key）、zeromev（**实测 530，服务已不可用**）、区块扫描自建、Dune 自定义查询、Nansen 标签、Arkham 实体归因、Bubblemaps 关联钱包。

### 3.4 一个真实算例（今天刚跑的）

同一时刻：

```
Chainlink ETH/USD        2236.52
Uniswap V3 池子价        2238.65
毛价差                    9.54 bps
gas                      0.09 gwei（25 万 gas ≈ $0.05）
```

看起来有 9.5 bps 的价差？扣两腿各 5 bps 手续费之后：

| 本金 | 扣费后毛利 | 扣 gas 后净额 | 成立？ |
|---|---|---|---|
| $10,000 | −$0.46 | −$0.51 | 否 |
| $50,000 | −$2.30 | −$2.35 | 否 |
| $200,000 | −$9.21 | −$9.26 | 否 |
| $1,000,000 | −$46.07 | −$46.11 | 否 |

**结论**：这是一个不成立的机会。而且注意 gas 只有 0.09 gwei——**gas 早就不是门槛了，手续费和竞争才是**。这就是为什么"看到价差就以为能套利"是这个领域最常见的错觉，也是为什么任何套利工具必须内置"扣除费用后的净额"这一步，而不是只报毛价差。

### 3.5 复刻别人的套利：能学到什么，学不到什么

技术上完全可做：

1. 拿到目标交易哈希 → `debug_traceTransaction` 或 `trace_replayTransaction` 还原 call tree
2. 抽出 swap 序列（哪个池、哪个方向、多少量）
3. fork 到该交易的前一区块，重放，验证利润数字
4. 换成你的地址再跑一次

第 4 步是分水岭：**换地址后利润一定会变**。原因有三——你的 gas 出价不同、池子状态已被前一笔交易推动、你不再享受对方的私有通道优先级。

所以"复刻"的真实产出不是"抢到同一笔钱"，而是**策略模板**：知道有人在 A 池和 B 池之间做三角、平均规模 $8 万、只在特定事件后出现。这个信息可以用来（a）理解市场结构，（b）做自己的策略，（c）在长尾场景里找同类机会。

### 3.6 我建议做的三个（按"和钱的距离"由近到远）

1. **稳定币 / LST 折价监控**：慢、可解释、不需要抢跑，最适合 Agent 输出"现在是不是该换仓"的判断
2. **清算预警**：读借贷协议的 health factor、预测预言机更新后的可清算仓位——**预警比执行更值钱**，因为执行要拼 gas
3. **新池 / 新链机会雷达**：长尾竞争少，但必须内置蜜罐与貔貅检测

**明确不碰**：三明治、狙击貔貅盘、任何以散户为对手方的策略。这不是道德洁癖——这三类正在被私有 mempool 和聚合器系统性消灭，投入产出比在快速恶化，且监管风险明确上升。

## 4. 对 BCA 意味着什么：三个产品形态

这三个方向都能落成"解释 + 验证"型工具，而不是"抢跑"型机器人。**这是关键的定位选择**：抢跑拼的是机房与硬件，BCA 永远赢不了；解释与验证拼的是工具覆盖与语义质量，这正是现有 142 工具的地基。

### 形态 A：白帽哨兵（Watchtower）

输入：协议地址列表 / 关注的合约
输出：异常交易告警 → 自动 fork 复现 → 可救援金额估算 → **救援交易草案（不自动提交）**

价值：把"20 分钟内完成救援"的能力产品化。收费可以是订阅 + 救援成功分成（行业惯例 10%）。

### 形态 B：套利复盘器（Post-mortem）

输入：一笔交易哈希
输出：路径还原（call tree → swap 序列）、毛利、手续费、gas、净利、**是否可被复现（fork 重放结论）**

价值：这是投研与合规审计的刚需——"这个地址是不是在跑机器人"、"我的交易被抽了多少"。

### 形态 C：资金流解释器

输入：地址 / 交易
输出：资金来源与去向、关联钱包、实体归因、风险标签

价值：Arkham / Nansen 的核心能力，但它们不做"用自然语言解释"。Agent 恰好能做这一层。

## 6. 风险清单（这部分比机会更重要）

| 风险 | 说明 | 对策 |
|---|---|---|
| **法律** | 没有 Safe Harbor 授权时，动别人合约里的钱可能被认定为攻击 | 只对已登记 Safe Harbor 的协议提供"救援草案"；其余只做只读复盘 |
| **误判** | 把正常的大额 swap 判成攻击，触发错误救援 = 帮倒忙 | 救援草案必须人工确认；不做自动提交 |
| **竞争** | 专业安全公司 21 分钟响应、有专线 | 不与它们抢"第一个发现"，做"第一个解释清楚" |
| **资金** | 救援本身需要 gas 与前置资金 | 用 flashloan 或赞助；不要求用户先充值 |
| **数据依赖** | zeromev 已挂，说明供应商不可靠 | 自建采集 + 多源冗余 |
| **伦理** | 工具被反向使用 | 不提供攻击构造能力；不提供私钥操作；模式库只做检测不做生成 |

## 7. 建议的第一步（不花钱、不碰真实资金、能完整证明能力）

选一个已发生的真实事件（例如 Balancer V2 或 Flooring Protocol），做一次端到端复盘：

1. 从链上数据还原攻击路径（读 trace → 调用树 → 资金流）
2. fork 到攻击前一个区块，重放攻击交易，验证损失金额与公开报道一致
3. 计算"如果当时有救援工具，最多能救回多少"
4. 生成一份救援交易草案（**不上链**）
5. 把整个过程做成一条 Agent 可执行的链路，现场演示

这件事的价值：**它同时验证了白帽与套利两条线的全部技术前提，而且零风险**。做完这一个案例，第 5 节的 P0 工具就有真实需求牵引，不是空想。
