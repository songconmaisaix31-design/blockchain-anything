让 Agent 接上区块链，

BCA 把官方 SDK、Foundry 和 MCP 服务收进一个入口。Agent 说一句「这个代币安全吗」， 它自己找到工具、补齐参数、拿到真实链上结果 —— 而不是让你先写三个适配器。

问题

Agent 不缺能力，缺的是「找得到」。

链上生态有上千个 SDK、CLI 和 MCP 服务。每一家都有自己的鉴权方式、参数命名和错误格式。Agent 不缺手，缺的是一张能用的地图。

01 / 发现

工具散落在十几个生态里

EVM 一套、Solana 一套、Sui 又一套。Agent 想查个余额，得先知道该用 viem 还是 Kit，还得知道参数叫 address 还是 pubkey。

02 / 鉴权

每家都要自己去申请密钥

Dune、Etherscan、RPC、Pinata…… 五个账号、五份配额、五种限流。撞墙时报错还不一样，排查一次能耗掉半天。

03 / 边界

没人敢让 Agent 自由写链

发现和授权混在一起最危险。一次幻觉就能让 Agent 把合约部署到主网，或者签一笔你不认识的交易。

方案

三个入口，一套实现。

同一份工具定义，三种调用方式。你在终端里试，在 Agent 里用，在自己代码里集成 —— 行为完全一致。

CLI 终端

在项目目录里直接问，直接调。最适合验证一个想法值不值得做。

bca find '这个代币安全吗' bca call goplus_token_security

MCP Agent

写进 Codex / Claude Code 的 MCP 配置，Agent 立刻多出一整套链上能力。

bca setup --client both --install bca mcp

TypeScript SDK 代码

嵌进你自己的平台。返回结构稳定，bigint 用十进制字符串，出错就抛异常。

const tk = createToolkit() await tk.invoke('evm_balance', {address})

常见问题

      
你大概会问这些。

    

    

      

        BCA 和直接用 viem / ethers 有什么区别？
        
不替代，是包装。BCA 内部调用的就是 viem、ethers、Foundry、官方 SDK —— 它解决的是「Agent 怎么知道该用哪个、参数怎么填、结果怎么读」。你写代码时仍然该直接用 viem；你让 Agent 干活时才需要 BCA。

      

      

        它会不会拿走我的私钥？
        
不会，架构上就不需要。公共链交易沿用宿主钱包授权流程，BCA 不代签、不托管。唯一的签署器是本地开发用途的 BCA_PRIVATE_KEY，公共 API 不接收私钥。一键部署也只面向本地 Anvil。

      

      

        能接我自己已经配好的 MCP 服务吗？
        
能。bca connect <name> 写入项目 .bca/mcp.json，之后 bca find '...' --server <name> 会读该服务真实的 tools/list。已有配置的请求头、传输方式和只读许可都会被保留，需要改就编辑配置文件或用新的配置名。

      

      

        支持哪些链？
        
EVM 系列最完整（含本地 Anvil、Foundry 工作流）。已完成适配的还有 Solana、Sui、Aptos、Arweave、Walrus、Safe。需要客观说明：注册不代表全部业务通过，各生态的实际验证范围写在仓库的 S2 记录里，公共测试网仍有未验证项。

      

      

        为什么本地功能免费？
        
因为成本结构如此。BCA 跑在你机器上，bca find 和 bca build 不花我们一分钱，收钱没有道理。真正有成本的是上游 API 调用 —— 那部分你现在是自己申请密钥直接付给上游，我们只是提供一个「帮你代持、统一计量」的可选方案。

      

      

        它能帮我赚钱吗？比如套利或者白帽救援？
        
它不会替你做交易，但会把"能不能赚"算清楚。五个新工具都只读：safeharbor_registry 查协议是否在链上登记了白帽救援与赏金条款；tx_call_tree 还原一笔交易到底做了什么；arb_scan 算价差，但**必须扣掉两条腿的手续费与 gas**；fork_replay 在本地 fork 上重放验证；mempool_watch 看内存池。现场实测：WETH/USDC 两个池子毛价差 5.77 bps，扣 35 bps 手续费后净额为负——工具的第一句结论就是"不成立"。自己钱包安不安全也可以一起查：approval_scan、wallet_posture、contract_posture。

      

      

        为什么还没发布到 npm？
        
项目首提交是 2026-10-19。先在源码安装阶段把 Windows / macOS 路径、公共测试网和账户型服务验证完，再发正式包 —— 宁可比预期晚，也不想让你 npx 下来是个半成品。
