## 一句话

BCA 是开源的链上能力网关：**框架免费、自带密钥免费、托管付费**。付费买的不是工具本身，是"不用自己申请和管理十几个上游密钥"。

## 一页速览

| 项 | 内容 |
| --- | --- |
| 产品 | 面向 AI Agent 的 MCP 链上能力网关，142 个工具 / 55 家上游 |
| 客户 | 用 Agent 做链上产品的独立开发者、小团队、Web3 产品方、Agent 平台 |
| 核心价值 | 把"接 44 个上游"压缩成"接一个 MCP"；把"写合约"换成"描述想法" |
| 收入 | 托管订阅（credits 计量）+ 企业授权，免费层永久开放 |
| 成本 | 上游 API 账单（可转嫁）、基础设施、模型调用（BYO 时为 0） |
| 护城河 | 工具目录的覆盖广度与标注质量；MCP 生态先发；开源带来的信任与集成 |
| 主要风险 | 上游涨价或收紧授权；MCP 成为协议级标准后差异化收窄；免费层成本失控 |

## 定价：五档

结构对标 Firecrawl 这类 API 产品——**免费额度起步、按用量分档、企业版定制**。区别在于计量单位：Firecrawl 按"抓取页数"，BCA 按"工具调用"（credits）。

| 档位 | 月付 | 年付（折后/月） | 含 credits/月 | 上游密钥 | 适用对象 |
| --- | --- | --- | --- | --- | --- |
| **Free / BYO** | $0 | $0 | 2,000 体验额度 | 自带 | 本地跑、自己配 key 的开发者 |
| **Starter** | $19 | $16 | 20,000 | 平台代持 | 个人开发者、原型验证 |
| **Pro** | $79 | $66 | 120,000 | 平台代持 | 独立产品、小团队日常使用 |
| **Team** | $299 | $249 | 600,000 | 平台代持 + 子账号 | 多项目并行、需要用量隔离 |
| **Enterprise** | 定制 | 定制 | 定制 | 可私有化 / 专属 RPC | 合规要求高、要求 SLA 与私有部署 |

年付口径按 12 个月一次性支付，折扣约 17%（$19 → $16、$79 → $66、$299 → $249）。

**关键设计：BYO 永久免费且不限量。** 自己提供上游密钥的用户，边际成本几乎为零，没有理由收费——这条既是定价策略，也是开源承诺的一部分。

## credits 计量规则

一次工具调用消耗多少 credits，由**执行代价**决定，不由"工具看起来重不重要"决定：

| 类型 | credits | 例子 | 说明 |
| --- | --- | --- | --- |
| 本地计算 | 0 | `content_cid`、`did_key_resolve`、`evm_chain` | 不访问付费上游，不应该收费 |
| 只读链上查询 | 1 | `evm_balance`、`viem_block`、`solana_balance` | 公共 RPC 或轻量上游 |
| 第三方付费数据 | 3–4 | `goplus_token_security`、`dune_query` | 上游按次或按量计费 |
| 组合诊断 | 4–8 | `workstation_diagnose` | 内部串多次上游调用 |
| 写操作 | 0 计价 | 交易提交 | 不靠写操作赚钱；权限与授权是安全边界，不是收费点 |

三条约束：

1. **调用失败不计费。** 上游超时、参数缺项、权限不足都退回 credits。
2. **先报价后执行。** `capability_search` 返回每个工具的 credits，Agent 可以在调用前判断成本。
3. **写操作不进入计量。** 避免"花钱就能多写链"的错误激励。

## 单位经济学

平台代持上游时，成本结构是「上游账单 + 基础设施 + 支付通道费」。按目录价反推单 credit 收入：

| 档位 | 单 credit 收入 | 估算上游成本 | 毛利（估） |
| --- | --- | --- | --- |
| Starter | $0.95 / 千次 | ~$0.30 / 千次 | ~65% |
| Pro | $0.66 / 千次 | ~$0.28 / 千次 | ~55% |
| Team | $0.50 / 千次 | ~$0.26 / 千次 | ~45% |

> 上游成本为**待验证**建模值：按 GoPlus 公开接口（免费额度内 0 成本）+ 公共 RPC（0 成本）+ Dune 付费查询（按量）混合作业结构估算。真实值需在获得首批付费用户的实际调用分布后回填。

两种上游承担方式，毛利结构完全不同：

| | 模式 A：平台代持 | 模式 B：BYO 自带密钥 |
| --- | --- | --- |
| 用户门槛 | 最低，注册即可用 | 需要自己去各家申请 key |
| 我们的上游成本 | 随用量线性增长 | 近似为零 |
| 毛利 | 45%–65%，取决于调用分布 | 接近基础设施成本 |
| 定价 | 按 credits 收费 | 免费 |
| 风险 | 上游涨价直接吃利润 | 无；但用户流失到"自己配" |

结论：**A 是收入来源，B 是信任来源。** 两者不冲突——B 层的用户是转化 A 层最优质的池子，也是上游成本失控时的泄压阀。

## 获客漏斗

```
GitHub / 文档站曝光
      ↓  装得上吗
npm exec 安装 → bca doctor 全绿
      ↓  跑得通吗
首次真实调用（content_cid / 余额查询 / 代币安全）
      ↓  愿意天天用吗
接入自己的项目（bca setup --client both）
      ↓  额度够吗
2000 credits 用完 / 想要团队协作
      ↓
付费
```

每一步的流失点与对策：

| 阶段 | 典型流失原因 | 对策 |
| --- | --- | --- |
| 曝光 → 安装 | 不知道能干什么 | 首页/README 用一句自然语言任务开场，而不是罗列工具 |
| 安装 → doctor 全绿 | npm 冷装超时、镜像缺版本 | 文档给出官方 registry 与手动安装兜底路径 |
| 首次调用 | 不知道该问什么 | 预置 8 个示例问题，覆盖只读、付费、本地三类 |
| 日常使用 | 只有演示价值 | 提供 `bca setup` 一键接入既有项目 |
| 免费 → 付费 | 2000 额度太小或太大 | 额度按"一次完整任务≈10–30 credits"设计，够跑几十次 |

## 竞品差异

| 对手类型 | 代表 | 他们的做法 | BCA 的位置 |
| --- | --- | --- | --- |
| 单点 API 产品 | Firecrawl（抓取）、各家链上数据 API | 一个能力做深，按页/按次计费 | 不替代它们，把它们的 MCP 接进同一层 |
| 链 SDK | viem、Solana Kit、Sui SDK | 提供库，开发者自己拼 | BCA 包一层，让 Agent 直接调用 |
| 合约工具链 | Foundry、Hardhat | 面向会写 Solidity 的人 | BCA 把编译/测试/部署变成 Agent 可调用的工具 |
| Agent 平台 | 各类 MCP 客户端 | 提供运行时，不提供链上能力 | BCA 是它们的能力供给侧 |
| 自建适配器 | 每个团队自己写 | 一次性投入，长期维护成本高 | 用一套标准工具集替掉这层重复劳动 |

真正的差异化不在"工具数量"，而在**每个工具的标注质量**：只读/可写、前置条件、失败语义、上游是谁。这决定了 Agent 能不能安全地自主决策。

## 评审应答速查

**Q：开源了怎么赚钱？**
托管是可选服务。自己配 key 的用户永远免费；愿意付钱的人买的是"不用管 44 个上游密钥、不用处理配额和合规"。这是 open-core 的标准结构，不是矛盾。

**Q：credits 定价会不会劝退？**
本地计算类工具（CID、DID 解析、链信息）计价为 0，日常只读查询 1 credit。2000 免费额度大约够跑几十次完整任务，足够判断有没有价值。

**Q：上游涨价怎么办？**
两条缓冲：一是 BYO 层用户不受影响；二是 credits 与上游成本挂钩，调价空间在毛利区间内（当前估 45%–65%）。真正的风险是上游停服，所以工具目录刻意保持多供应商冗余。

**Q：为什么不做自己的链上数据源？**
做数据源是重资产生意，与"网关"定位冲突。我们的价值是编排与标注，不是囤数据。

**Q：和直接让 Agent 调 viem 有什么区别？**
Agent 自己调 viem 需要知道 RPC、ABI、精度、错误码。BCA 把这些封成带 Schema 和失败语义的工具，并且能跨生态（EVM/Solana/Sui/Aptos）统一调用。

**Q：免费层会不会被刷爆？**
免费层默认要求自带密钥，平台代持额度只给注册用户且按月重置；写操作始终需要显式授权，不存在"刷免费额度去发交易"的路径。

**Q：企业版卖什么？**
私有化部署、专属 RPC 与上游额度、审计日志、SLA，以及把内部工具注册进同一套目录。

**Q：现在有付费用户吗？**
没有。当前是 v1 开源阶段，本文的定价与单位经济学是**待验证假设**，用于对齐预期，不是已验证的经营数据。
